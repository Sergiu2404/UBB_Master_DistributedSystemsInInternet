
# Configuring, Compiling, and Running a Dropwizard Project

Follow these steps to set up and run a Dropwizard project:

---

## 1. Setup a Dropwizard Project

### a. Add Dropwizard Dependency
Create a new Maven project or use an existing one. In the `pom.xml`, include the Dropwizard dependency:

```xml
<dependency>
    <groupId>io.dropwizard</groupId>
    <artifactId>dropwizard-core</artifactId>
    <version>4.0.0</version> <!-- Replace with the desired version -->
</dependency>
```

---

## 2. Create the Dropwizard Project Structure

### a. Main Application Class
Create the main application class that extends `io.dropwizard.Application`:

```java
package com.example;

import io.dropwizard.Application;
import io.dropwizard.setup.Bootstrap;
import io.dropwizard.setup.Environment;

public class MyApplication extends Application<MyConfiguration> {

    public static void main(String[] args) throws Exception {
        new MyApplication().run(args);
    }

    @Override
    public String getName() {
        return "my-application";
    }

    @Override
    public void initialize(Bootstrap<MyConfiguration> bootstrap) {
        // Initialize application-specific components
    }

    @Override
    public void run(MyConfiguration configuration, Environment environment) {
        // Register resources, health checks, and more here
        final MyResource resource = new MyResource(
            configuration.getTemplate(),
            configuration.getDefaultName()
        );
        environment.jersey().register(resource);
    }
}
```

### b. Configuration Class
Create a configuration class that extends `io.dropwizard.Configuration`:

```java
package com.example;

import com.fasterxml.jackson.annotation.JsonProperty;
import io.dropwizard.Configuration;

import javax.validation.constraints.NotEmpty;

public class MyConfiguration extends Configuration {
    @NotEmpty
    private String template;

    @NotEmpty
    private String defaultName = "World";

    @JsonProperty
    public String getTemplate() {
        return template;
    }

    @JsonProperty
    public void setTemplate(String template) {
        this.template = template;
    }

    @JsonProperty
    public String getDefaultName() {
        return defaultName;
    }

    @JsonProperty
    public void setDefaultName(String defaultName) {
        this.defaultName = defaultName;
    }
}
```

### c. Resource Class
Create a resource class annotated with JAX-RS annotations:

```java
package com.example;

import javax.ws.rs.GET;
import javax.ws.rs.Path;
import javax.ws.rs.Produces;
import javax.ws.rs.core.MediaType;

@Path("/hello-world")
@Produces(MediaType.APPLICATION_JSON)
public class MyResource {

    private final String template;
    private final String defaultName;

    public MyResource(String template, String defaultName) {
        this.template = template;
        this.defaultName = defaultName;
    }

    @GET
    public String sayHello() {
        return String.format(template, defaultName);
    }
}
```

---

## 3. Create a Configuration File
Create a YAML configuration file, e.g., `config.yml`:

```yaml
template: Hello, %s!
defaultName: Dropwizard
```

---

## 4. Build the Project

### a. Compile the Project
Use Maven to compile the project:
```bash
mvn clean package
```

This will generate a JAR file in the `target` directory.

---

## 5. Run the Application

Use the following command to run the Dropwizard application:

```bash
java -jar target/your-app-name-1.0-SNAPSHOT.jar server config.yml
```

- Replace `your-app-name-1.0-SNAPSHOT.jar` with your JAR file's name.
- The `server` argument starts the HTTP server.
- The `config.yml` file provides the configuration.

---

## 6. Access the Application

By default, Dropwizard runs on port `8080`. Access the application at:
- **Resource Endpoint**: `http://localhost:8080/hello-world`
- **Admin Interface**: `http://localhost:8081`

---

## 7. Testing the Application

You can test the application using tools like:
- **curl**:
  ```bash
  curl http://localhost:8080/hello-world
  ```
- **Browser or Postman**.

## 8. Add Health Checks

The `TemplateHealthCheck` in Dropwizard is a simple custom health check implementation used to monitor the health of an application. It validates the expected behavior of functionalities like template rendering or service availability.

### Purpose of `TemplateHealthCheck`

In a typical Dropwizard application, health checks ensure key parts of the application are functioning correctly. The `TemplateHealthCheck` checks whether a template-based operation works as expected by validating its output.

---

### Example Implementation

Here's an example of how `TemplateHealthCheck` might look:

### Implementation

```java
package com.example.health;

import com.codahale.metrics.health.HealthCheck;

public class TemplateHealthCheck extends HealthCheck {
    private final String template;

    public TemplateHealthCheck(String template) {
        this.template = template;
    }

    @Override
    protected Result check() throws Exception {
        // Check if the template renders correctly
        final String testString = String.format(template, "TEST");
        if (!testString.contains("TEST")) {
            return Result.unhealthy("Template rendering failed");
        }
        return Result.healthy();
    }
}
```

### Key Components
1. **Template Field**: Stores a template string, typically a placeholder text for testing.
2. **check() Method**:
  - Generates a string using the provided template.
  - Validates if the rendered output contains the expected placeholder.
  - Returns a `Result` indicating health status (`healthy` or `unhealthy`).

---

### Registering the Health Check

To use the `TemplateHealthCheck`, register it in the `run` method of your Dropwizard application.

### Example Application Code

```java
@Override
public void run(MyConfiguration configuration, Environment environment) {
    final String template = configuration.getTemplate(); // Assume the template is configured
    final TemplateHealthCheck healthCheck = new TemplateHealthCheck(template);
    environment.healthChecks().register("template", healthCheck);
}
```

---

### Testing the Health Check

Once registered, test the health check by visiting the `/healthcheck` endpoint of your Dropwizard application (e.g., `http://localhost:8081/healthcheck`).

### Healthy Output:
```json
{
  "template": {
    "healthy": true
  }
}
```

### Unhealthy Output:
```json
{
  "template": {
    "healthy": false,
    "message": "Template rendering failed"
  }
}
```

---

### Use Cases of `TemplateHealthCheck`
1. **Template Verification**: Ensures templates used for rendering outputs (e.g., Freemarker, Mustache) work correctly.
2. **Custom Validation**: Adapt the check for other validations, like configurations or dynamic content.

By using health checks like `TemplateHealthCheck`, Dropwizard applications can quickly identify and respond to issues in production.
